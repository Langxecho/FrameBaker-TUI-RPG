# 人工制作教程：从零件到持枪动画

## 0. 先准备一张制作任务卡

写下角色显示名、稳定 ID、正面朝向、目标屏幕内身高、配色、必做动作、可穿戴部位、武器类型、参考图来源。目标场景当前是 320×180；这是整个战场的画布，**不是要求单个人物做成 320×180**。先在实际战场缩放下确认剪影可读，再选制作分辨率。

枪手现有候选采用以下九个表现动作：`idle`、`basic_prepare`、`basic_fire`、`basic_recover`、`stimulant`、`emp`、`orbital`、`hit`、`death`。这是当前项目动作映射的起点，不是所有新职业都必须采用的动作表。动作时长和触发语义与 LIAF 负责人核对，不能靠拉长动画来改变技能冷却。

先完成“待机 → 举枪 → 开火 → 回稳”一套短闭环，一把武器通过后再做另外两把。不要一开始同时修改二十多个动作。

## 1. 生成或手绘部件

1. 在素材库上传一张完整人物参考图，锁定同一个人物、朝向和服装。生成中心可以辅助生成部件表；提示词见 [方法论](art-methods.md)。
2. 部件至少能独立覆盖：头、躯干、骨盆、左右上臂/前臂/手、左右大腿/小腿/脚；武器另存，不画死在手里。
3. 在部件网格编辑界面检查每格内容，调整分隔线、移动格内图、拆分/合并或擦除杂边。完整人物图无法通过普通网格切割自动得到被挡住的手臂，需先补图或重生成部件表。
4. 抠图后用棋盘、深底、浅底检查。接头要有隐藏在另一部件下的重叠区域，肩、肘、膝不能恰好切到轮廓边缘；试转动后再决定重叠长度。
5. 保留无损原图、透明分件、网格与裁剪记录。不要把第一次裁切覆盖到唯一原稿。

**完成标准：** 每个部件独立、命名明确、不缺角、不夹带其他肢体，缩小后依然可辨。

## 2. 建立骨架

在项目列表新建「骨骼」项目。项目类型不能原地改成逐帧项目。骨骼项目有角色、装备、武器、动作、动画、发布六个工作区；不同版本中文标签略有差异，以标签语义为准。

1. 在动作/骨架资产工作台创建或选择 Skeleton。编辑内置只读动作时先复制；项目引用的 MotionClip 必须属于同一个 skeletonId。
2. 建议的人形层级如下（名称是教学建议，实际引用使用项目稳定 ID）：

```text
root
└─ pelvis
   ├─ chest
   │  ├─ head
   │  ├─ upper_arm_left → forearm_left → hand_left
   │  └─ upper_arm_right → forearm_right → hand_right
   ├─ thigh_left → shin_left → foot_left
   └─ thigh_right → shin_right → foot_right
```

3. 将骨骼原点放在真实关节：上臂根在肩、前臂根在肘、手根在腕。子骨骼位置相对父骨骼，不是相对屏幕。骨端显示 `tipOffset` 不会自动决定子骨骼位置。
4. 先把人物放在可看清分件的中性姿态，固定脚底和肩线，再制作持枪姿势。不要先做动画，再靠修改整套骨架补救比例。

## 3. Region 绑定，也就是当前可用的“蒙皮”

在角色工作区选择骨架，添加部件附件，并为它选择骨骼、素材、大小、pivot、绘制顺序。

| 字段/概念 | 制作者如何理解与操作 |
| --- | --- |
| Skeleton | 骨架；决定哪些关节如何连接 |
| Slot / Attachment | 骨架上的显示位置 / 放在该位置的图片附件 |
| materialId、imageSlot | 图片身份，以及使用原图 raw 还是抠图 processed；不要选错图片版本 |
| size | 图片在骨骼空间中的宽高；保持原比例，禁止随手拉长手臂图掩盖骨长错误 |
| pivot | 图片绕哪一点转动，例如上臂的肩关节 |
| rest | 部件相对骨骼的静态位置、旋转和缩放 |
| drawOrder | 遮挡顺序；远侧手臂通常在躯干后，近侧手在枪前 |

**坐标容易出错的地方：** 图片编辑器通常左上原点、Y 向下；FB Region pivot 以图片**左下角**为 `(0,0)`，右上为 `(1,1)`，骨骼 Y 向上。裁后图片宽 W、高 H，关节在图片左上坐标 `(x,y)` 时，初始换算为 `pivot=(x/W, 1-y/H)`。例如 100×200 图片的关节在 `(50,20)`，pivot 是 `(0.5,0.9)`。透明边裁剪后必须按新图片尺寸和新关节位置重算，不能沿用旧比例。

绑定后逐根旋转一点，再恢复：肩不脱离胸、肘不露空、膝有覆盖、脚不脱离小腿。AI 可以做坐标换算与批量填写；人工必须检查这一轮。

## 4. 配置可穿戴身体与装备

BodyProfile 可以理解为“这副身体能穿什么、挂在哪里”。角色图片的 Slot 与装备容量 Slot 不是同一概念。

1. 在装备相关工作区创建/选择本角色 BodyProfile，绑定正确 skeletonId。
2. 定义装备槽位（例如 weapon、support），填写容量和允许的 tags；定义挂点 Socket，绑定具体骨骼及局部偏移。
3. 创建 EquipmentDefinition。纯属性芯片可以 `visualMode=none`；外挂机械件用 `attached`；替换身体部件用 `replacement`；效果表现用 `effect`。是否采用某种模式取决于真实内容，不能强迫每件数值装备都长出一张身体贴图。
4. 护甲/义体替换时明确 `replacesParts`、`hidesSlots`；逐件试穿，看旧身体是否仍重叠显示，卸下后是否恢复。
5. 先测试单件，再测互斥组合。槽位已满时拒绝应保留原装备，不是“点击没生效”。两把双手武器不能同时装；切换时先卸下上一把。

这里做的是**外观和兼容性**；装备属性、稀有度、掉落和特殊机制由后端定义，不放进骨骼变换里。

## 5. 调整双手握枪

1. 武器素材只含枪，不含手。将主握位设在扳机握柄，副握位设在护木支撑处；枪口挂点放在真实枪口，不放在整张图片的最右边透明边缘。
2. 选择 `holdMode=two_hand`，设置主手、`primaryGrip`、`secondaryGrip`、`muzzleSocket`，声明两个占用槽位。长枪副握位不同，不照抄短枪坐标。
3. 先对齐主手和枪，再调整辅手及肘部。辅手两骨 IK 可辅助：检查 upper/lower/endBone、弯曲方向、mix 与拉伸设置。IK 负责接触，不负责设计美观的肘部姿态。
4. 在装备组合预览里查看，单纯角色动作预览不一定包含你正在编辑的装备。开启挂点显示定位，正常检查画面时隐藏文字。
5. 依次测待机、预备、开火最大后坐、回稳。枪不应脱手，前臂不能无限伸长，枪托不能穿胸，肩膀不能为满足握点而飞出躯干。
6. 投掷/注射等技能允许辅手离枪。当前候选曾采用烘焙好的局部关键帧、固定 IK mix=0 来实现松手；不要假定有已交付的逐时间 IK mix MCP 轨道。若固定 IK 会把辅手锁住，先用受支持的烘焙姿态方案验证，不能凭空新增协议。
7. 长短枪姿态差别明显时为武器制作独立动作，用 `actionOverrides` 把基础动作 ID 映射到**包内实际动作 ID**。不要误填 MotionClip ID、中文展示名或不存在的动作。

独立传说武器也采用这个入口：身体骨架合同兼容、独立武器素材、独立动作覆盖、枪口/特效挂点。需要新的权威机制另交后端，不在动画回调中计算命中。

## 6. 人工制作关键帧

在动作工作区创建/复制 MotionClip，在绑定角色上编辑关节姿态。时间单位是**秒**，24 FPS 只是预览/采样频率。

1. 先放少量能表达意图的关键姿态：起始、准备、发力、最大后坐、恢复。人工看清动作重心后，再让 AI 辅助填中间关键帧。
2. 移动播放头到目标时间，选中骨骼，调整平移/旋转，写入相应轨道关键帧；保存后重新播放，确认只是当前关键帧变化而非误改整副 Rest Pose。
3. 待机的首尾要连贯；死亡应播放一次并保持终态，不能又站起来循环。动作 speed、repeat、loop 与 clip.loop 要一起核对。
4. 制作 hit 时避免意外把主武器甩到身体另一侧。死亡、技能释放中的松手是有意设计，不能被自动“握点纠正”抹掉。
5. 先看 0.25/0.5 倍速找穿帮，再看正常速度判断节奏，最后缩到终端实际像素尺寸。放大看着精致不等于战场中可读。
6. 特效、枪口闪光和弹道单独交付表现资源。动作里的开火标记只表达表现时刻；是否命中、伤害多少仍取后端。

当前 v3 不支持的 warp/Mesh 不用于正式交付动作。若某种形变是必要需求，记录具体失败样例交给工具开发；不要导出时悄悄删掉轨道后声称完全保真。

## 7. 导出与迭代

进入第 6 步「发布导出」，修复错误并输出 `.fbanim v3`。保留制作工程和全部源素材依赖，不能只交运行时包；现有普通 v2 导出也不能当作含装备的完整工程备份。

交给 LIAF 制作者构建 `.class` 和 `.equipment`，在正式终端预览。每次更改生成新候选摘要；按 [验收表](acceptance.md) 对比相同时间画面，再进入后端准入。`aic_publish_v3` 返回构建信息不等于已经在客户端看到角色，更不等于角色已进入游戏。
