# 角色素材方法论

## 参考图与提示词

先生成一张完整的身份参考图，再生成部件表。每次生成都固定人物描述、朝向、镜头、比例和调色板；不要让模型同时改变人物身份和分件方案。图片提示词至少写清：

```text
用途：320x180 像素战斗场景中的角色素材制作。
主体：同一名角色，完整身体，右朝侧向，清晰粗黑轮廓，赛博朋克像素画，块面颜色明确。
构图：整个人物居中，四周保留 20% 安全边距，不裁切，不遮挡。
部件表：头、躯干、骨盆、左右上臂、前臂、手、大腿、小腿、脚分别可辨，部件之间留窄缝，
不要把枪画在手上；另放一把独立侧视武器。
背景：纯品红 #ff00ff，平面无阴影。
禁止：文字、logo、水印、第二人物、额外武器、漂浮碎屑、渐变背景。
```

“参考图只供风格和身份”要写进提示词，避免生成器复制参考人物的衣服和姿势。武器提示词单独生成：完整武器、右朝侧视、标志性轮廓、真实枪口、20% 留白、纯品红色键、无手无角色。已有枪手候选的可复用结构正是这套写法；它只产生候选，不能跳过人工选图。

## 分割与抠图

优先使用人工确认的网格，而不是让模型猜“上臂/前臂”。例如 4×4 部件表使用行优先、从 0 开始的 cell；先确认每格含义，再裁切。AIC `split_material_parts` 的 `rows/cols` 范围是 1..8，最多 64 格，支持 RGB 色键、容差和有限 `magentaDespill`。它只做确定性裁图、去色键、透明边裁剪，不是语义人体分割，也不能补回被遮挡部件。

分割后逐格检查：主体像素数量、边界框、透明边、是否把枪托/手指切掉、是否残留色键。透明边裁剪会改变尺寸，pivot 必须按新尺寸重算。色键只删除与边界连通的背景；角色身上的紫色镜片、火焰、电光等相近颜色不能靠提高容差粗暴删除。

当自动抠图误删特效时，保留主体蒙版和特效蒙版两层，人工逐帧补回，不要把一次成功的样本算法扩到整套动作。怪物的火焰/电光尤其要做首中末帧和连续播放检查。

## 从持枪参考制作默认空手

先确定角色本体和装备的边界。默认无装备时，角色贴图和绑定中都不应出现武器；参考立绘的枪不能直接变成默认身体的一部分。保留原持枪候选作比较，再制作独立空手候选。

1. 同时查看完整参考、手部裁片和武器裁片。枪柄、扳机和手指往往交错，仅删除枪图层可能留下柄部残像，也可能删掉握枪手指。
2. 先恢复完整手套和手指，再决定空手手形。自然微握的空拳可以沿用，不必无依据改为五指张开。将来装备后的握持手形单独制作。
3. 可局部修补时，以手指、手套、武器三类蒙版区分，使用邻近原图的相应明暗色。不能把所有青色/黑色像素统一涂成手套色；这会在裸露手指上形成深灰方块，也会损坏服装青色饰边。
4. 修补后检查正常游戏比例、双手最近邻放大图和浅/深背景，确认手指轮廓、无枪柄残片、无透明缺口，并确认手腕、衣服和赤红虹膜等非目标区域没有改变。
5. 若原图遮挡过多，保留失败候选，使用受限局部生成或重新制作手部，不能用粗糙几何手形冒充完成。记录原始参考、蒙版、修补方法和新素材 ID。

## Region“蒙皮”与握点换算

当前 Region 绑定只保存图片到骨骼的挂接关系。关节连续性依赖图片有足够重叠、正确 pivot 和 drawOrder；它不会像 Mesh 权重一样自动弯曲一张图片。制作时让肩、肘、膝藏在上层部件覆盖区，宁可多留一点隐藏像素，也不要在关节处精确裁断。

FB 的 pivot 是图片左下角坐标：`pivot=(x/W, 1-y/H)`，其中 `(x,y)` 是左上原图中关节位置，W/H 是裁剪后的新尺寸。骨骼使用 Y 向上、时间使用秒；这些换算交给脚本或 AI 计算，但人工必须在画面中复核。

## 逐帧与骨骼的选择

- 角色身体、可换武器、可调姿态：骨骼项目 + `.fbanim v3`。
- 普通怪物及有大量独立像素效果的动作：逐帧 PNG/拆帧工程，再由后端内容流程形成 `.monster`；不要伪造骨骼。
- 子弹轨迹、枪口闪光、斩击光、命中特效：作为独立表现资源/挂点事件处理，不能塞进角色身体图，也不能让动画决定权威命中。

## 低成本 AI 策略

图片和视频生成消耗的是时间，结构化 API 调用消耗的是上下文与请求次数。先用一张参考图和一个部件表建立身份，再复用 source material、seed/checkpoint 和 idempotencyKey；不要为每个动作重新生成人物。让 AI 处理批量枯燥项（尺寸/边界/pivot 表、缺失 ID、采样报告），让人处理少量高价值项（肩线、握枪、重心、动作节奏、特效保留）。所有生成与改写都保存 prompt、插件、参数、source SHA、jobId 和结果 SHA。
## 关键帧密度与插值函数

骨骼动画的流畅度由两个因素共同决定：**关键帧的分布密度**和**关键帧之间的插值函数**。仅有足够采样率（120fps）不保证流畅播放，如果关键帧间隔过大或插值曲线不符合物理规律，连续播放时会出现"一卡一卡"的感觉。

### 关键帧分布原则

1. **在快速动作段增加密度**  
   蓄力、甩投、挥砍等快速动作段，关键帧间隔应控制在 0.1-0.15 秒以内。如果 .36→.55 跨越 0.19 秒且中间没有中间帧，即使使用平滑插值，视觉上仍会感觉突变。

2. **在力量传递链上错峰**  
   腿→腰→胸→肩→肘→腕的力量传递链中，每个关节的峰值时刻应错开 0.04-0.08 秒。例如腰在 .55 秒达到最大转动，肩在 .61 秒跟随，肘在 .67 秒前导，腕在 .73 秒甩出。如果所有关节同时到达极值，动作会失去层次感和传递感。

3. **在姿态转折点必须有帧**  
   后移→前移、下沉→上升、蓄力→释放的转折点必须有明确关键帧，不能靠插值"猜"过去。例如 EMP 从后移蓄势（.55）到前移甩出（.79）之间，必须有 .67 的转向帧，否则中间段的腰部旋转会线性插值而失去真实感。

### 插值函数选择

关键帧定义姿态和接触时点，插值函数定义它们之间的路径与速度。先区分经过、反向和停留节点，再选曲线；不能按“快动作/慢动作”给每段统一套缓动。

**Perlin Smootherstep（5次多项式）**  
```typescript
const smooth=(v:number)=>{const u=Math.max(0,Math.min(1,v));return u*u*u*(10+u*(-15+6*u));};
```
- 适用于有意从静止开始并停下的独立过渡；不要直接套到连续经过点之间。
- 特点：两端速度和加速度为零，中段速度并不恒定。逐段使用会让每个中间节点停一次，呼吸和回握也可能因此变僵。

**Ease-in-out-cubic（3次立方）**  
```typescript
const easeInOutCubic=(v:number)=>{const u=Math.max(0,Math.min(1,v));return u<0.5?4*u*u*u:(u-1)*(2*u-2)*(2*u-2)+1;};
```
- 也是两端速度归零的时间映射，不能仅凭名称或曲线阶数判断力量感；中点还存在加速度不连续。
- 完整的起止动作可按节奏使用；投掷途中的经过节点应传递速度，不应逐段归零。出手后保留身体和腕的随动，不在放手帧突然停下。
- 连续段可用共享切线的 Hermite 曲线，并约束过冲。离散烘焙时检查相邻节点两侧速度；接触锁定、道具显隐和手形切换单独保留。

### 实践案例：EMP r42 的教训与 r43 修正

**r41 问题诊断**  
- 关键帧分布：8 个身体节奏帧，8 个手部路径帧  
- 最大间隔：.36→.55（0.19秒），.55→.67（0.12秒），.79→.94（0.15秒）  
- 全程使用 smootherstep 插值  
- 用户反馈动作“一卡一卡”；上述帧数和间隔本身不足以确认原因，还需区分曲线停走与播放器掉帧。

**r42 历史试验（不是推荐配方）**  
1. 增加关键帧密度：  
   - 身体节奏：8 → 14 帧（新增 .26, .45, .61, .73, .865, 1.07）  
   - 手部路径：8 → 14 帧（新增 .25, .45, .615, .735, .865, 1.07）  
   - 最大间隔降至 0.12 秒

2. 优化插值函数：  
   - 快速甩投段（.55→.94）改用 ease-in-out-cubic  
   - 其他段保持 smootherstep

3. 腕部错峰强化：  
   - 新增 .25, .45, .61, .735, .93 腕角度帧  
   - 松手动作从 .79 突变改为 .735 开始过渡

这次加密仍逐节点缓动归零，且重建曲线时丢失了 r41 的四条手形/道具显隐轨道。r43 改为保形三次插值连续传速，并显式继承这些轨道；结构修正不代表完整连续播放已经通过。详情见连续性记录（ECHO 本机未入库：`docs/superpowers/plans/2026-10-06-gunner-r43-continuity.md`，见 `skill/README.md` 缺失清单）。

**验收标准**  
- 1x 连续播放无明显卡顿  
- 快速段有明显加速→减速节奏  
- 腿、腰、胸肩、肘、腕的力量传递可读，峰值间隔按动作和时长决定，不固定要求某个秒数  
- 手形切换在关键时刻完成（.14 握持，.79 松手，1.62 回握）

### 制作检查清单

实际制作时，在配方中逐条检查：

- [ ] 关键帧覆盖表意、接触和转折时点，密度按路径误差决定，不以固定间隔验收  
- [ ] 力量传递链上各关节的峰值时刻错开  
- [ ] 姿态转折点有明确关键帧（不依赖插值猜测）  
- [ ] 经过点两侧速度连续，只有明确停留或反向才减速到零  
- [ ] 检查整条空间弧线、速度峰值及出手后的随动，避免多段假停顿  
- [ ] 施法与恢复边界位置、旋转、速度及手形一致；数值容差按模型单位与实际像素尺度设定  
- [ ] **最关键**：在工作台 1x 连续播放多轮，实际观察流畅度

数值通过、网格无翻面、接触表截图生成成功**都不能替代**连续播放的人工审核。
