# 角色验收与交接单

每个候选包单独建收据，至少记录：projectId、revision、源素材及 SHA、动作 ID/时长/loop、BodyProfile、装备 ID、`primaryGrip`/`secondaryGrip`/`muzzleSocket`、插件和 prompt、jobId、包 SHA、构建版本、诊断结果、FB 截图和终端截图路径。

## 视觉门禁

- 无装备：默认空手，掌心/手指/手套完整，无枪柄、扳机或切割残片。参考图持枪也不能例外；空手和握持手形分别验证。
- 中性待机：肩、颈、躯干、骨盆、腿脚没有明显断层。
- 每把武器逐动作：主手握点、辅手握点、枪托、枪口与身体关系正确；开火后坐和恢复连贯。
- 技能松手：该松手的动作真的松手，其他动作不意外脱手。
- 逐帧查看首/中/末与慢速播放；再用当前正式视口、角色显示比例与最终窗口尺寸检查可读性。当前游戏战场为 1024×224、八个可见位置；320×180 是历史基础规格，不是新布局约束。
- 必须完整1x连续播放：关键帧之间弧线、速度连续，经过点无非预期停顿，发力与承接有节奏；检查施法/恢复边界与循环。关键帧数量和数值通过不作为流畅证据。
- 多背景检查透明边、色溢出、特效是否被抠除。
- 局部补画附原图、补画、二值蒙版、新 material 与像素差异；检查蒙版外不变，掌面、松指、腕口与接触连续。工具创建成功不等于美术签收，详见局部修复流程（ECHO 本机未入库：`skill/fb-character-authoring/references/local-repair-and-performance.md`，见 `skill/README.md` 缺失清单）。
- FB 兼容预览和正式终端取同一个动作 ID、时间和装备组合。若不同，先标记为消费契约问题，保留两边截图，不自行改姿态掩盖差异。

## 结构门禁

- `aic_get_diagnostics` 无 error；所有 material、bone、socket、action 引用存在。
- v3/v4 包的实际版本与 published reference 一致，包含纹理闭包、BodyProfile、装备与动作覆盖；Mesh/runtimeWarp 按目标版本和消费端资格验收，不静默丢弃或降级。
- 双手武器声明两个占用槽位和 `secondaryGrip`；槽满时加载失败并保留原组合。
- 时间以秒保存；动作 loop/repeat/speed 与预期一致。

## 交接顺序

1. 制作者交工程、源素材、版本一致且经资格确认的候选 `.fbanim v3/v4` 和收据。
2. LIAF 组包人员保留实际版本，将内容绑定游戏身份，产生 `.class` / `.equipment` 候选。
3. 客户端在离线 LIAF 工作台读取并截图；这一步只证明终端预览，不证明后端准入。
4. 后端使用自己的导入验证和注册流程；机制、数值、奖励、技能仍由后端注册。
5. 运营/测试在隔离环境验证角色进入战斗，再记录可发布版本。生产部署另有门禁。

任何一门失败都保持候选状态，不覆盖旧包，不用“诊断为空”替代人工视觉签收。

宿主插值、相邻段速度、真实输入与截图闭环及包准入收据见[跨仓库交付与验收](../../rpg-content-production/references/production-handoff.md)。
