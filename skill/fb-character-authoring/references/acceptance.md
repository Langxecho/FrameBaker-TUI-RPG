# 角色验收与交接单

每个候选包单独建收据，至少记录：projectId、revision、源素材及 SHA、动作 ID/时长/loop、BodyProfile、装备 ID、`primaryGrip`/`secondaryGrip`/`muzzleSocket`、插件和 prompt、jobId、包 SHA、构建版本、诊断结果、FB 截图和终端截图路径。

## 视觉门禁

- 中性待机：肩、颈、躯干、骨盆、腿脚没有明显断层。
- 每把武器逐动作：主手握点、辅手握点、枪托、枪口与身体关系正确；开火后坐和恢复连贯。
- 技能松手：该松手的动作真的松手，其他动作不意外脱手。
- 逐帧查看首/中/末与慢速播放；再用 320×180 实际战场尺寸查看可读性。
- 多背景检查透明边、色溢出、特效是否被抠除。
- FB 兼容预览和正式终端取同一个动作 ID、时间和装备组合。若不同，先标记为消费契约问题，保留两边截图，不自行改姿态掩盖差异。

## 结构门禁

- `aic_get_diagnostics` 无 error；所有 material、bone、socket、action 引用存在。
- v3 包包含纹理闭包、BodyProfile、装备与动作覆盖；没有被静默丢弃的 warp/Mesh 能力。
- 双手武器声明两个占用槽位和 `secondaryGrip`；槽满时加载失败并保留原组合。
- 时间以秒保存；动作 loop/repeat/speed 与预期一致。

## 交接顺序

1. 制作者交工程、源素材、候选 `.fbanim v3` 和收据。
2. LIAF 组包人员将 v3 内容绑定游戏身份，产生 `.class` / `.equipment` 候选。
3. 客户端在离线 LIAF 工作台读取并截图；这一步只证明终端预览，不证明后端准入。
4. 后端使用自己的导入验证和注册流程；机制、数值、奖励、技能仍由后端注册。
5. 运营/测试在隔离环境验证角色进入战斗，再记录可发布版本。生产部署另有门禁。

任何一门失败都保持候选状态，不覆盖旧包，不用“诊断为空”替代人工视觉签收。
