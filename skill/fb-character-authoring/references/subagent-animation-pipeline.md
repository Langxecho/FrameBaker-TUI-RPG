# 多代理动作制作流水线（枪手实践）

用于一个已有人物、分件、标准rig和认可动作基线的项目。不从头重做角色。主代理负责目标、串行MCP写入与最终画面审查；子代理只做独占离线动作配方。

## 分工与最小交付

1. 读职业文档的动作语义、时长、武器与魔改边界，制作动作矩阵。被动、BUFF、区域与弹道不必各造一次施法。
2. 基础组制作进入/退出、受击/失衡、死亡/定格/胜利；武器组制作单发节奏变体；技能组制作三项施法和收势。有限并发，6.1sol仅在用户选用时覆盖模型。
3. 每组独占`scripts/<character>_<group>.ts`及测试，返回`action/clip/reviewTimes/notes`。禁止并发写同一工程、共享rig或生成队列。
4. 配方输入是冻结候选。数值检查覆盖所有三角形，不能用只显示前64条的诊断摘要宣称零翻面。站立查脚位；死亡允许离地，查着地、闭眼与定格一致。
5. 主代理以当前revision、唯一幂等键原子集成，冻结candidate。装配preview中的binding不可直接写回本体，必须取无装备原始binding。
6. 同候选截图先看整身表意，再看关节/遮挡；不足以表示投掷/注射/通信时，重做空间路径而非仅增加运动幅度。
7. 最后在真实工作台1x检查施法与收势连接、循环、动作切换及播放性能，记录观察范围。静态接触表不是连续播放验收。

## 本轮可复用经验

- 蓄势、发力、承接、回位错峰，主枪与骨长不拉伸；先解决脚底与握点，再塑造节奏。
- 姿态节点与帧间函数一起交付：注明哪些点经过、反向或停留。经过型节点用连续切线传速，不能每段都ease-in-out归零；新增中间帧后检查速度峰值及节点两侧速度，避免动作变成多段启停。
- 重烘焙骨骼曲线时逐项继承手形、道具显隐、接触和事件轨道。只替换旋转轨道会让已完成的握持/松手丢失，数值几何测试未必发现。
- 远侧辅臂越过身体往往被遮住，不能永久移到前层破坏原遮挡。优先选择身体轮廓外可读路径，并分离枪口与技能手的高度。
- 技能全烘焙双臂时，专用制作装备可省略可选`secondaryHandConstraint`；`mix:0`不一定停止求解，勿忽略几百条不可达告警。正式武器原配置保持不变。
- 关节圆弧修形的相邻横向顶点应共用中性轴弧长；各自变弧长可造成剪切翻面。补画和修形各司其职，不能把“数值无翻面”当关节画得自然。
- 死亡不能只是浅蹲；可利用现有视角做失力侧倒，但缺少背面时不承诺转身/翻滚。闭眼属于独立眼皮，不替换义眼。
- Qwen道具表一次生成三格：注射器、EMP、腕式终端，保留源图。色键边缘残留要实际看透明图；专用连通背景清理只处理明确纯色道具，不能套用所有角色。
- 道具是独立Region且默认隐藏，只在对应技能显示。现有附件轨道可作制作预览；未来正式事件播放接入另行验证，不让动画marker结算伤害。
- 展示循环连接施法、收势和短停留。正式技能0.6/1.2/2.5秒不因此改变，死亡不自动站起。
- 死亡松手需同时处理三件事：移除专用装备辅手约束、握持手形换回本体空手、独立枪体轨道抵消手部矩阵。对真实本体附件ID做断言；不能把装备装配后的binding写回本体。落地后检查枪体世界位置和死亡定格衔接，不只检查骨骼矩阵。
- 出现播放卡顿，先记录分阶段耗时、RAF间隔和有界全局Long Task。帧间隔大但相邻渲染工作小，不足以认定蒙皮慢或GC；CPU平均值不能替代真实页面尾帧。记录候选/动作/装备、浏览器刷新和是否前台。
- 本机冻结候选数值测试需显式开关，普通测试不能依赖作者服务端口和UUID。

## 停止条件与真实交付

预先设有限编辑/生成预算、单问题最多三轮。预算耗尽先保留最佳候选、明确未过项，不能新建工程绕过；后续追加要显式记录。生成成功、数值通过、FB画面、客户端同包、后端准入分别签收。没有足够证据时review=revise，不adopt或发布。

本轮来源与具体ID见枪手动作库记录（ECHO 本机未入库：`docs/superpowers/plans/2026-10-05-gunner-action-library.md`，见 `skill/README.md` 缺失清单）；不要把其中本机UUID用作新人物默认值。
