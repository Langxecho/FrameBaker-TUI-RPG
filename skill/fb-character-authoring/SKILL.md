# FrameBaker 人机协作角色制作 SOP

制作者从这里开始。目标是交付**可继续编辑的制作工程、完整 v3 资源包和真实画面验收记录**。只生成一张好看的图，或只通过数据校验，都不算角色做完。

## 先分清由谁做什么

| 工作 | 人负责 | AI 可以协助 |
| --- | --- | --- |
| 外形与分件 | 确认形象、补遮挡区域、修透明边和关节覆盖 | 写提示词、生成候选、按明确网格切图、统计像素 |
| 骨骼与绑定 | 确认关节位置、层级、遮挡关系 | 创建 Region 绑定、换算坐标、查引用、批量调整参数 |
| 动画 | 设计关键姿态、动作节奏、握枪与松手、逐动作签收 | 生成可编辑草稿、插值、采样接触误差、列出异常时刻 |
| 换装 | 确认武器实际握位与穿戴外观 | 配置槽位、挂点、替换隐藏、动作覆盖、校验组合 |
| 交付 | 确认 FB 和真实终端中的画面都合格 | 构建、摘要、资源闭包、复现与差异报告 |

当前采用 **Region：每张部件图片跟随一根骨骼**。它不是多骨骼顶点权重 Mesh 蒙皮。`meshSkinning`、`runtimeWarp` 不在当前 v3 交付能力内；UI 能编辑某种形变，不代表终端能播放。不要答应“一键自动蒙皮并直接上线”。

## 按任务阅读

1. 第一次制作：读 [人工操作教程](references/human-workflow.md)，照着完成一把武器的完整小样，再扩展其他动作。
2. 生图、分图、蒙皮遇到困难：读 [提示词与制作方法](references/art-methods.md)。含实际枪手案例的成功方法和失败原因。
3. 让 AI 操作 FB：读 [MCP 辅助制作](references/mcp-assistance.md)。先查工具能力，再发写入；附可复制任务提示与参数示例。
4. 验收与交接：读 [检查表与交接单](references/acceptance.md)。同包、同动作、同装备、同时间对比，区分制作问题和消费端问题。
5. 怪物、道具及进入游戏的全过程：读后端仓库 `skill/rpg-content-production/SKILL.md`（常用本机位置 `F:\CodeProject\挂机game`），按角色/怪物/装备/道具选择流程。

## 开工时先确认环境

- 读本仓库 `AGENTS.md`、`README.md`，核对所用工程与服务的实际仓库，保留已有素材与工作区改动。
- 本 SOP 位于主 FB 仓库根目录 **`skill/`**，不是现有插件打包工具的 `skills/`。手动告诉 AI“读取 `skill/fb-character-authoring/SKILL.md`”即可使用；不要假定任意 AI 客户端会自动扫描这个自定义目录。
- 2026-09-29 核对：`F:\CodeProject\FrameBaker-TUI-RPG` 的 `shy` 有骨骼/装备 UI 和基础 MCP；`F:\CodeProject\FrameBaker-TUI-RPG-aic` 的 `codex/aic-fb-pipeline` 工作树另有 AIC 骨骼写入和网格分件 MCP。增强能力仍有本地未提交文件。**本 SOP 的存在不代表这些代码已合入 shy。** 以运行服务的 `tools/list` 为准，不自行切分支或合并。
- 新机器不要依赖本机 UUID；先在素材库、项目列表查到实际对象。已有枪手 revision 15 是候选，不是合格成品；本次 SOP 不会自动修改它。
- FB 默认端口 3000，容易与游戏后端冲突。已有服务优先复用；新启动示例为在所选 FB 仓库执行 `$env:PORT='3025'` 后 `bun dev`。先确认端口未被占用，不同时打开两个进程写同一制作库。

## 三个不能混淆的产物

- FB 第 6 步「发布导出」的 `.fbanim v3`：骨骼、贴图、动作、BodyProfile、装备表现的制作交付。
- 客户端 LIAF `.class` / `.equipment` / `.monster`：绑定游戏身份、后端已注册机制与表现资源的内容包。当前不要把职业包叫成受支持的 `.player`。
- 后端导入及运营应用：决定游戏可用的内容和权威计算；FB 不计算伤害、掉落或技能效果。

普通「导出骨骼包」是 v2 路径，会遗漏 v3 的装备等内容；不要用改后缀的方式交付。数值校验、视觉签收、服务端准入、运营应用、生产部署分别记录。

## AI 执行原则

先读取有界摘要，再修改指定对象；沿用稳定 ID、当前 revision 和幂等键。保留原图和修改前工程快照，不直接写 SQLite，不把示例脚本中的旧 project/material ID 当成当前项目。生成任务超时先按 jobId 对账，不能盲目重新提交。共用 ComfyUI 时先卸载上一个插件加载的模型并确认显存回收，再切下一个，详见 MCP 指南。

当前用户已选择人工负责枪手姿态、动画与穿戴握持。后续调用本 skill 时按该分工协作；本次编写教程不等于授权继续修改动画或发布候选资源。
