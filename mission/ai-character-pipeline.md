# AI 角色制作流水线：FrameBaker 任务卡

契约编号：LIAF-AIC rev D1。状态：方向确认、接口提案、尚未实现。中央权威设计位于后端仓库 `挂机game/mission/ai-character-pipeline.md`；本页只定义 FrameBaker 的工作与交付边界，不替代跨仓库合同。本提案不提升 R4、Q06、G1、G2、G3 的状态，也不改变既有 FB-00…04 的验收记录。

## 目标与边界

先制作一个**非正式职业**的人形测试角色、一种武器、`idle`/`attack`/`hit`/`death` 四个动作，并在真实客户端完成一次从攻击发起到命中表现的完整演出。随后只换武器或调整体型，验证局部重算、局部修复与未受影响资产保持稳定。Gunner 和 `rifle_two_hand` 只能作为历史兼容样例，不作为此任务的产品职业或验收捷径。

第一阶段采用标准人形骨架和 Region 附件：骨骼层级与运动、角色图片部件切分、附件绑定、动作曲线分别建模。参考蒙皮只是编辑器中叠加的参考图/视频，不等于可发布角色蒙皮；Region 附件按单骨骼变换，不等于 Mesh 顶点权重。当前 `.fbanim v3` 发布仍拒绝 `meshSkinning` 和 `runtimeWarp`；这些能力不能写成已支持，必要时另提显式烘焙和损失合同。

素材生成、抠图、切分、命名与装配允许使用开源模型或已有媒体插件；“没有 API 调用费用”不等于免费执行。每次任务记录 token、wall time、计算资源与重试预算，并保留模型标识/版本、参数、seed、输入与实际输出字节的摘要。插件目前 MCP 仅有 `list_media_plugins`、`get_media_plugin`、`generate_with_media_plugin`，适用类型由运行时查询结果决定；安装、配置、密钥管理不能假称已有 MCP 能力。

## 现状与接口原则

当前 MCP 的 `create_project` 只能创建默认逐帧项目，`update_project` 只能改名称和文件夹；任意 JSON 不能借这两个工具写骨骼文档。HTTP 可建 `kind=skeletal` 项目、管理 Skeleton/MotionClip 资产并 PUT 骨骼文档，服务端会核查绑定、素材和资产引用；但发布诊断、预览与 `.fbanim v3` 下载主要在浏览器侧，尚不足以构成无需手工点击的制作流水线。实现前须复核 `apps/server/src/mcp/`、`apps/server/src/api/skeletalProjects.ts`、`apps/server/src/api/animationAssets.ts`、`apps/web/src/publishDiagnostics.ts` 和 `apps/web/src/skeletalExport.ts` 的当时行为。

新增 MCP 应暴露共享领域操作，并复用与 HTTP/浏览器相同的验证和发布内核，不逐个映射按钮。下列是**拟议能力**，不是现有命令：项目/资产语义摘要、按骨骼/部件/动作局部查询、原子增量 patch、局部诊断、阶段性预览、发布构建与可复核任务状态。摘要返回稳定 ID、依赖、修订与诊断计数；详细曲线、图片字节和大文档只按需获取，避免每轮把全量 JSON 塞入上下文。

原子 patch 要有 `baseRevision` 乐观并发条件、幂等键、允许的操作集合、变更路径及预期依赖；完整验证后事务写入，冲突返回当前 revision 和有界局部差异，拒绝部分成功。同幂等键与相同输入返回原结果，输入冲突才拒绝。

单位/坐标继承 `docs/pose-motion-system.md` §4 与 `packages/shared/src/animation.ts`：资产默认右手系、Y 上/Z 前、`x,y,z,w` 四元数、`T*R*S`；MotionClip 时间为秒。画布 Y 下和其他接口的毫秒经显式 adapter 转换。动画轨道替换 Rest Transform 通道；编辑 patch 不能改变这一语义。MCP 外层单位声明、镜像及采样精度在接口提案中明确，不重写资产格式。优先复用 `sampleMotionClip`、`upsertMotionKeyframe` 等纯函数，IK/曲线求解在本地执行并返回受影响范围，不要求语言模型手填大量逐帧数字。

场景拆层不等于人物部件分割，必须检查关节遮挡余量与装配结果。`idle/attack/hit/death` 在本文只表示动作类别，技术 ID 在样例规格中映射，不改写现有注册键。

任务应持久化并可恢复：请求输入摘要与幂等键确定一次逻辑运行，阶段/尝试/错误码/产物摘要结构化保存；中断后从已验证阶段恢复，不重复覆盖好资产。支持完成/失败通知；没有推送能力的客户端只做有界退避轮询，超过预算明确停止。每阶段记录生成来源、模型参数、seed、实际文件 SHA-256/字节数以及失败和重试成本，不能只保存 prompt 或预期路径。

## 任务与依赖

| 任务 | 依赖 | FrameBaker 交付物 | 正向验收与必须拒绝的情况 |
| --- | --- | --- | --- |
| AIC-FB-01 能力矩阵与样例基线 | D1 中央边界；可立即开工 | “UI 操作→现有 MCP/HTTP/仅浏览器→缺口”矩阵；一个不代表正式职业的最小人形输入、素材来源和旧 v2/v3 发布差异复核 | 用真实接口和包复核矩阵；拒绝把参考蒙皮、Region、Mesh 权重混称或把拟议工具名写成现有命令 |
| AIC-FB-02 语义摘要、局部查询与原子 patch | AIC-FB-01；中央 ID、单位、revision 合同 | 共享领域 API/MCP 提案与实现、读写 schema、并发/幂等/回滚 fixtures、HTTP 与 MCP 等价证据 | 可只查询一根骨骼/一个附件/一条动作轨；局部改动不重写其他实体；幂等重试返回原结果；过期 revision、非法单位/引用、同幂等键输入冲突和中途错误均不产生部分提交 |
| AIC-FB-03 素材与部件生成编排 | AIC-FB-02；可用模型/插件实测 | 角色与武器素材分层、抠图/切分/命名与 Region 绑定来源链；持久任务、成本和恢复记录 | 同 seed/参数/输入可追溯到实际字节；缺少插件、运行时、模型或输出素材时明确失败；不将整角色图冒充骨骼部件 |
| AIC-FB-04 骨架、绑定与动作局部诊断 | AIC-FB-02/03；坐标和动作语义冻结 | 骨架/BodyProfile/附件、武器 socket、四动作及本地 IK/曲线求解；按实体和采样时间返回诊断 | 检查闭包、姿态、手与武器对齐、裁剪/遮挡、标记和镜像；断骨、缺图、错误挂点、越界关键帧须指出具体路径/时间 |
| AIC-FB-05 阶段性拼图与发布内核 | AIC-FB-04；消费者能力矩阵确认 | 可机器读取的局部及整角预览、真实纹理加载、共用发布诊断、确定性 `.fbanim v3` 包与 manifest/digest | 浏览器和服务端校验同结论；无能力或缺资源时阻断；禁止静默丢装备/动作/事件、禁止把 warp/mesh 打包成可消费 v3 |
| AIC-FB-06 联合闭环与局部修改 | AIC-FB-05；客户端和后端测试接入 | 可编辑工程、包字节摘要、四动作采样、一次完整攻击命中证据；换武器或改体型的前后 revision/依赖和差异报告 | 真客户端播放、命中时序由后端权威决定；修改只重算受影响部件/动作，未改内容摘要稳定；失败包、错误装备适配、缺命中表现均不得报通过 |

AIC-FB-01、AIC-FB-02 的接口提案与 AIC-FB-04 的诊断分类是最小可开工项；生成模型选择、插件安装和正式职业身份不阻塞这些设计工作。AIC-FB-05 需等客户端实际能力反馈再冻结发布合同。各任务状态初始均为“待开始”；任务完成只能按本仓证据记“待联合验收”，跨仓库真实客户端验收由中央任务记录。

## 验收记录

每次交付附工程/素材/包的稳定 ID 与 SHA-256、三仓库代码修订、合同修订、模型与插件标识、参数和 seed、实际字节与成本、正负测试、采样画面或机器预览、客户端消费结果及未验证项。一次成功 HTTP 保存、浏览器画面或静态 fixture 不单独证明零手工流水线，也不推进 R4/Q06/G1/G2/G3。
