## 3. PNG ZIP（怪物）缺什么

对照契约「边界 A」最小集合，当前拆帧包只有像素：

## 4. v2 / v3 入口差异（真实工程路径）

1. **日常骨骼页「导出骨骼包」= 仅 v2。** `export.ts` 只调 `buildFbanimV2Entries`。不会带上项目里已做好的装备、BodyProfile、约束。装备等于没导出。这不是「静默烘焙」，是 **整类数据未打包**。
2. **第 6 步发布 = v3。** 十阶段诊断；`runtimeWarp`/`meshSkinning` 在 `publishDiagnostics` 与 `animationPackageV3` 双重拒绝。有 warp 的工程 **不能** 走 v3，也 **不能** `migrateV2PackageSource`。
3. **v2 仍可能含 warp 字节**（clip/binding JSON），消费者若按 v2 加载且忽略能力位，行为未定义。
4. **canonical fixtures** 在 `tests/fixtures/fbanim-v3/manifest.json`，11 个 contractId，策略为精确字节。`minimal-region` 只是其中一项。发布页夹具按钮默认打 `minimal-region` 样例，**不能**证明任意用户工程等于这些 fixture。
5. 仓库内 **没有名为 Gunner 的 skeleton id**；G3 身份未在代码冻结。最接近的现成合同是 `rifle-right-primary` / `rifle-left-primary` / `dual-pistol` / `equipment-effect` fixtures，不是「标准 Gunner 工程」。
6. `WeaponProfile.muzzleSocket` 是相对 Transform，BodyProfile **标准 semantic 列表没有 muzzle**（只有 `weapon_hand_*` 等）。枪口挂点要 Q-06 决定：独立 socket id，还是手骨 + muzzle Transform。

**复现：** 同一骨骼工程分别点「导出骨骼包」与「导出 .fbanim v3」，解压 manifest `version` 为 2 vs 3；v2 无 `entry.equipment`。对含 warp 的绑定点发布导出，应出现 CAPABILITY_REJECTED / PACKAGE_BUILD_FAILED。

## 5. warp / mesh / 附件偏移：限制与烘焙代价

- 制作：自由 warp 由 `warpImagePixels` 栅格化（worker 优先）；偏移矩阵为 `boneWorld × rest × offsetMatrix(t)`。
- 运行时 v3：**拒绝** `runtimeWarp`、`meshSkinning`。没有「批准烘焙模式」开关；要给不支持 warp 的客户端，只能事先把变形烘进 PNG 并去掉 warp 轨道（今日无此导出模式）。
- 烘焙代价（提案，待 Q-07 测）：按 clip 时长 × 24 采样 × 变形附件数做离线栅格；失去动态换装下的活变形；包体积近似「每动作每附件一组 PNG」。未烘焙就把整角色拍成一张序列，**不能**再声称骨骼兼容（契约已写明）。
- 附件偏移（非 warp）可留在 clip 里，v3 合成器会编进 runtime motion，成本低于 warp。

## 6. 面向 Q-01 / Q-02 / Q-06 / Q-07 的提案（R0，供总体负责人冻结）

### Q-01 最小 schema 增量

- **逐帧/怪物交付**不新后缀：在现有 ZIP 内增加 `manifest.json`（建议 `format: "liaf-frames"` 或沿用团队已有 `.monster` 内部 JSON，由规范源定名），字段最小集：`id`、`schemaVersion`、`digest`、`actions[]`（稳定 ID、loop、facing、fps、frame 列表、每帧 durationSeconds）、`origin`、`sockets?`、`markers?`、`files[]` digest。
- **禁止**把怪物 PNG ZIP 直接改扩展名为 `.monster` 而不加清单。
- **骨骼：** G1 不走 v2 工程按钮；LIAF 只收 v3 `.fbanim`。v2 保留为制作预览。v2→v3 仅当无 runtime warp；装备必须从发布路径进包，不允许「v2 当完整角色」。
- 兼容：旧怪物 ZIP 视为 `schemaVersion: 0` 原始像素，消费者拒绝绑定，只允许人工导入制作工程。

### Q-02 坐标 / 时间 / 标记 / 镜像

- 像素空间：Y 向下，原点与逐帧导出一致（统一包围盒左上 + `originX/Y` 指向对象原点）。骨骼 rest/socket 沿用现有 Transform（translation 3 + quat 4 + scale 3）。
- 时间：运行时一律 **秒**；24 FPS 仅采样密度。逐帧 `step.duration`（格）导出时写 `durationSeconds = duration / fps`，禁止只写格数。Clip 事件保持 `[0, duration)` 半开。避免逐帧取整累加：每帧存绝对 `t0`。
- 朝向：显式 `facing: "left"|"right"`；怪物制作锁左，导出必须写上。镜像同时变换 origin、挂点 x、方向（与 BodyProfile `mirrorAxis: "x"` 一致）。
- 标记：只允许表现事件（`weapon.fire`、`effect.trigger`、脚步等）。**不要**把 `combat.hitbox.*` 解释为权威判定；提案从素材合同中改为 `fx.contact` 或标明 `presentationOnly: true`。

### Q-06 标准 Gunner 身份

- 提案：冻结一个 **skeletonId + BodyProfile id**（名称可叫 `gunner`），双手 `weapon_hand_left/right`，`rifle_two_hand` 用现有 `holdMode: "two_hand"` + `secondaryGrip` + `muzzleSocket` Transform。
- 现成 fixture `rifle-right-primary` 仅作采样参考，**不能**在未核对工程的情况下改名为 Gunner。
- 不支持的能力：`runtimeWarp`、`meshSkinning`；动态换装只到 equipmentAssembly + 替换/隐藏槽。缺 socket 则发布失败，不静默丢装备。

### Q-07 性能与烘焙预算（测量方法，阈值 G1 前补实测）

- 测量：导出耗时、包字节、解码峰值、24Hz 采样挂点误差（对照 clip 解析）。
- 预算提案（待测）：单怪物动作包 &lt; 8MB；Gunner 角色 v3 &lt; 32MB（已有 v3 limit `maxTotalBytes` 128MB 为硬顶）；挂点误差 &lt; 0.5px；warp 烘焙离线、不进战斗线程。
- 未测前不得宣称 G1 性能通过。
